# CHG-001 HTML ingestion cleaner: handoff (2026-11-04)

Branch `feature/chg-001-html-ingestion-cleaner`. The cleaner is built, unit
tested, and measured against every exported workbook and against a restored
copy of the database. Two checks remain, both of which need a crawl or the
review UI rather than credentials. Design and measurements are in
[chg_001_html_ingestion_cleaner.md](chg_001_html_ingestion_cleaner.md).

## What the branch does

Crawled regulator pages used to be stored byte for byte in
`regulations.document_html`. This branch passes every write through an
allowlist cleaner (`utils/html_clean.py`, built on nh3) at the repository
layer, so scripts, event handlers, iframes, forms and `javascript:` links
never reach the stored record. Headings, paragraphs, lists, tables, links,
images (including inline `data:image` figures) and inline styles are kept.

The change touches only new writes: inserts, promotions, modified rows and
version rows. **No existing row is rewritten.** Rows stored before this
change are covered by CHG-002, the display sandbox, on a separate branch.

## How the database check was done

The dev server at `10.11.12.76,1437` is not reachable from outside the office
network, so the backup was restored locally:

- SQL Server 2025 Express, ODBC Driver 17 and sqlcmd installed through winget.
  The backup is a 2025 build, so 2022 Express cannot restore it.
- `uc2-db_2026-09-22.bak` restored as `uc2-db` on `localhost\SQLEXPRESS`.
- `.env` points at it with blank credentials, which the repo treats as
  Windows authentication. The dev-server block is kept in the file, commented
  out. `.env` and `*.bak` are git-ignored.
- `python -m scripts.html_clean_scan --samples 5 --text` read every row.

The local copy is also a safe place to try the writers for real: nothing
written to it is seen by anyone else.

## End-to-end run (CBK Kenya, 2026-11-04, local copy)

Same crawler and repository as the scheduler's `_crawl_into_db`, with
`analyse=False` so no LLM call was made. CBK Kenya is absent from the
September copy, so pass one is all inserts.

| | Pass 1 | Pass 2 |
|---|---|---|
| crawled | 234 | 234 |
| new / modified / unchanged | 234 / 0 / 0 | 0 / 0 / 234 |
| hashes or `updated_at` moved | | 0 |
| time | 12 min (PDF extraction) | 4.5 min |

Pass two's "unchanged" is the per-document comparison of live hash against
stored row; the orchestrator's inventory-hash early exit only runs after that
classification. The three rows that carry HTML (the other 231 are PDFs) were
checked against the October workbook, which holds the raw pre-cleaner
markup: stored html equals `clean_html(raw)`, visible text equal, content
hash identical to the workbook's. This is the direct proof that a cleaned
stored copy does not produce a false "modified".

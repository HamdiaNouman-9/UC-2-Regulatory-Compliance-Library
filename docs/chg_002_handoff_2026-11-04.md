# CHG-002 HTML display sandbox: handoff (2026-11-04)

Branch `feature/chg-002-html-display-sandbox`, based on
`feature/chg-001-html-ingestion-cleaner`. Built, tested in Node and Python,
and checked in the real review UI against a restored copy of the database.
Design, decisions and measurements are in
[chg_002_html_display_sandbox.md](chg_002_html_display_sandbox.md).

## What the branch does

The review page used to put stored regulator HTML into its own DOM after
five regular expressions. Now the HTML is cleaned by DOMPurify with the same
allowlist as the ingestion cleaner, then shown inside a sandboxed iframe
that cannot run scripts, reach the page, its storage or the API, or submit a
form. Links open in a new tab with `noopener noreferrer`. Images and inline
styles still show. If the sanitiser fails to load, the page shows escaped
plain text, never raw HTML.

This covers every stored row, including the 42,444 written before CHG-001.

## How to run the tests

```
.venv/Scripts/python.exe -m pytest tests/test_html_display.py tests/test_html_clean.py
cd tests/js && npm install && npm test
```

If the allowlist in `utils/html_clean.py` changes, run
`python -m utils.html_clean` and commit the regenerated
`web/html_allowlist.json` and `web/html_allowlist.js`; the Python test
fails until you do.

## Not on this branch

- Images are still fetched from regulator servers when a page is shown. The
  frame's CSP allows `img-src https: http: data:`; narrowing it to a proxy or
  to specific hosts is a separate decision.
- Relative links inside stored HTML resolve against the UI's origin, as
  before. `scripts/absolutise_document_html.py` is the separate fix.
- The frame is a fixed 360 px with its own scrollbar, as the old box was. A
  frame that grows with its content would need a script inside it, which
  the sandbox forbids by design.

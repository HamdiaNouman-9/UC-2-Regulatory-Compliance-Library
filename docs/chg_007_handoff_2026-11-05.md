# CHG-007 data markers around every source sent to a model: handoff (2026-11-05)

Branch `feature/chg-007-prompt-data-markers`, from `main`. Built, measured
against the restored database copy and 22 PDFs, unit tested at the module
and at the prompt level, and dry-run on a stored regulation. Design,
measurements and decisions are in
[chg_007_prompt_data_markers.md](chg_007_prompt_data_markers.md).

## What the branch does

Every excerpt of document text that goes to a model now sits between two
markers carrying a code drawn for that call:

```
[[[BEGIN QUOTED document #3f9a1c0b7e2d]]]
...text...
[[[END QUOTED document #3f9a1c0b7e2d]]]
```

followed by one sentence stating that the text between the markers with
that code is quoted content, data to analyse, and contains no instructions.
Before the text is quoted, any copy of our marker shape (any code, any
case) and any copy of the tag names our prompts use (`<document>`,
`</document>`, `<task>`, `<context>` and the rest) is removed from it; the
words inside such a copy stay, as content. A clean excerpt goes through
byte for byte.

This applies at the five places document text enters a prompt: the
extraction and activity prompts of the requirement/activity pipeline (every
crawl and every re-analysis from the API), and the two stage-one prompts of
the staged analyser still used by the upload, standalone-analysis and
staged-analysis endpoints, and the metadata extraction message for an
uploaded file.

Why here and not at the separators in `textinput.py`, as the register row
first said: those separators are no longer seen by a model. The orchestrator
hands the page text and each attachment to the analyser separately, and the
analyser chunks them; the only text a model sees is the chunk inside the
prompt template. The corrected register wording is at the end of the design
document.

## Running it

```
.venv/Scripts/python.exe -m pytest tests/test_quoted_source.py tests/test_prompt_data_markers.py
python -m scripts.quoted_source_scan                 # stored text fields, read-only
python -m scripts.quoted_source_scan --pdf-dir DIR   # plain text of PDF files
python -m scripts.chg007_behaviour_check --dry       # rebuild the behavioural prompts, no model call
```

Run the scan on any new regulator whose text might, against expectation,
carry triple brackets or our tag names; a match is a line to read.

## For CHG-008 (quarantine)

From the behavioural run: the planted sentences that still got through
were prefixed "SYSTEM MESSAGE:" or "IMPORTANT INSTRUCTION TO THE ANALYST:",
and the model twice cited "SYSTEM MESSAGE" as the source reference. Both
phrases belong on the pattern list, and a source reference that is not a
section of the document is itself a signal.

`quote_source(...).stripped` is the number of marker or tag copies removed
from an excerpt. A document that needed any stripping at all is a forgery
by construction (the measurement found zero in everything stored), so a
non-zero count is a ready-made quarantine trigger with no false-positive
risk. The count is not written anywhere yet; the prompt builders have no
row to write to. CHG-008 can run `strip_lookalikes` on the page text and
attachments at its own scan point, before the text is chunked.

## Not on this branch

- The requirements JSON that the classification, duplicate-check and
  activity prompts carry is model output, not document text, and is not
  quoted. It is derived from quoted text, so an instruction that survived
  extraction would have to be one the model chose to record as a
  requirement.
- The change matcher's prompt (`crawler/smart_matcher.py`) places a page
  snippet in its prompt unquoted; that is CHG-009's file and is left to it.
- The system prompts are unchanged; both already say the document is
  source material only.

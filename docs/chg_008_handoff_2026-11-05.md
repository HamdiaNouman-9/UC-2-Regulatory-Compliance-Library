# CHG-008 a document that tries to instruct the model is held for a person: handoff (2026-11-05)

Branch `feature/chg-008-injection-quarantine`, from `main`. Built, measured
in observe mode over everything stored, unit tested at the module, the
orchestrator gate, the release and the review endpoint, and run end to end
on the restored database copy with the real review page in a headless
browser. Design, measurements and decisions are in
[chg_008_injection_quarantine.md](chg_008_injection_quarantine.md).

## What the branch does

Before a document is analysed, its page text and each attachment are
scanned for three things: multi-word instruction phrases ("ignore all
previous instructions", "SYSTEM MESSAGE:", "instruction to the analyst:"
and the rest of `config/injection_patterns.yml`), copies of the analyser
prompts' own markers and tags, and a large share of hidden text (from
CHG-006's counts: over 10 % hidden on a page or file of at least 2,000
characters). A hit does not stop the crawl or lose the document.

In **enforce** mode the row is saved with `status = "quarantine"`, the
reason, the matched phrase and its context are written to
`extra_meta["injection_guard"]`, both steps are logged QUARANTINED, and
analysis is skipped for that row only. The review page shows an amber
block with the reason, the phrase in context and two buttons; the API's
re-analysis endpoints refuse the row. Accept, through the run's own
decision endpoint, sets the row active, records who released it on the
guard's record, and starts the analysis that was skipped; reject records
the rejection and leaves the row out.

In **observe** mode (the default: `mode: observe` in the config file,
`INJECTION_GUARD_MODE` in the environment overrides it) the same record and
an OBSERVED step are written and nothing else changes: status untouched,
analysis runs. Switch to enforce only after the observe pass below has
been repeated on any newly onboarded regulator.

The detector sits behind a two-method interface, so a local classifier
can be added beside the pattern list without touching the callers.

## Running it

```
.venv/Scripts/python.exe -m pytest tests/test_injection_guard.py tests/test_injection_guard_gate.py tests/test_injection_guard_release.py tests/test_injection_guard_review_api.py
python -m scripts.injection_guard_scan                 # observe pass over the database, read-only
python -m scripts.injection_guard_scan --pdf-dir DIR   # over PDF files
INJECTION_GUARD_MODE=enforce ...                       # or mode: enforce in config/injection_patterns.yml
```

Run the observe pass before enforcing on a newly onboarded regulator, and
read every hit: a phrase that occurs in genuine text is removed or
tightened before enforcement, never after.

## What to watch after merge

- `regulations.status` was empty on every row of the September data. The
  review's decisions write it (`active`, `reject`, `withdrawn`), and now
  the guard writes `quarantine`. Nothing else reads it, and the "active"
  filters in the repository and the API are on `regulation_versions`.
- The guard reads CHG-006's hidden-text counts from the row's `extra_meta`
  and nothing else from that branch; with CHG-006 merged the hidden-text
  rule is live, without it that rule never fires and the other two do.
- A hit that cannot be recorded in enforce mode is still held (logged
  `ERROR` then `QUARANTINED`); a failure inside the guard itself is logged
  `ERROR` and the document is analysed as before. Both appear in
  `processinglogs` under step `injection_guard`.
- `apis/pipeline_api.py` loads `.env` with `override=True`, so an
  environment variable set for the API process is replaced by the file's
  value. `INJECTION_GUARD_MODE` is read from the environment by the
  guard, which is fine for the orchestrator jobs; for the API process it
  only matters if the API ever runs the guard, which today it does not.

## Not on this branch

- A classifier detector. The interface is there (`Detector.scan`); the
  pattern list is what ships.
- A planted sentence with no instruction wording, no marker copy and no
  hidden text passes all four changes. That is the residual the CHG-007
  measurement left, and this change makes it a reviewer's call only when
  there is a fingerprint to see.
- The review page's block appears on the regulation view; the run review
  list already shows `review_status = "quarantine"` on the change row and
  needs no change.

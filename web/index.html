    ▶ Run a regulator's crawl

    Crawls the live source and classifies documents as new / modified / unchanged / disappeared, then writes the result to a local Excel workbook only -- nothing touches the production database unless you separately approve it (dynamic_crawler/formfill/api.py, its own service on its own port). "check against production DB" (below) seeds that comparison with what's actually already in the library, read-only, so an already-onboarded regulator like MISA correctly reports "no new updates" instead of re-reporting its whole inventory as new every time. A workbook name lets a second LOCAL run also compare against the first, on top of that. "reuse last crawl" replays the crawl already on disk instead of hitting the live site again; MISA's own config already runs list-only (no per-document detail pages), matching the fast daily monitoring check.

    ⚠ Regulators with no recent updates

    A regulator is flagged when its newest document version (new, modified or withdrawn) is older than its interval. Intervals are set in config/staleness.yml. The scheduler also runs this check daily and logs the result.

    🤖 Analysis model

    The OpenRouter model used for requirement and activity analysis. A change applies to analyses that start after you save it. Non-default models run without provider pinning, so results are less reproducible run to run.
